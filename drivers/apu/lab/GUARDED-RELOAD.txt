Start-Guarded-Config-Reload.cmd starts the administrator helper. It starts
the recovery task, confirms its live heartbeat, and selects the existing
configuration-only candidate through normal PnP installation. The driver
switch is itself the live reload being tested. The 180-second reply deadline

Without acknowledgment, the local watchdog selects the previously verified
patched ASUS prototype and verifies its selected INF/kernel hash. It then
requests a Windows restart, needed to recover from the observed Code 43
after live replacements. The restart request does not force applications
closed. Unsaved-work prompts can delay it. No additional UAC is required
for the SYSTEM recovery task. Test Mode and trusted certificates remain.

The watchdog temporarily holds an execution-state request to keep Windows
and the display awake during the test. It releases that request on exit.
It is separate from the graphics-switching process and can still run if
only the graphics/display path stalls. A full Windows/kernel hang or power
loss can prevent any local watchdog from running on time.

The recovery task also has a boot trigger so an interrupted unanswered
trial can resume recovery after Windows starts again. It unregisters itself
after acknowledgment or successful recovery. It refuses to start if the
prepared scripts changed, the healthy prototype is absent, or Test Mode is
off. The acknowledgment and timeout compete for one atomic decision file;
neither can overwrite the decision that already won.
